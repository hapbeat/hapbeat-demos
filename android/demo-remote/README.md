# Hapbeat Demo Remote（Android）

展示・デモ運営用の Android リモコンアプリ。同じ LAN 上の Meta Quest に対して次を行う。

- **アプリ切替 / アプリ操作**: Demo Switch プロトコル（UDP 7710、`hapbeat-contracts` の `specs/demo-switch-control.md`）で `SWITCH` / `CONTROL` を送る。M5 controller（`hapbeat-demo-switch-controller-firmware`）の代替として使え、併存もできる
- **Hub のプリセット 1〜3**: 同じく Demo Switch（`PRESET_GET` / `PRESET_SET` / `PRESET_START`）で、Hub に保存されたプリセットを読み、書き換え、開始する（adb 不要）
- **Hub の設定・デモ開始**: Hub の管理画面と同じ設定（`HUB_SETTINGS_GET` / `HUB_SETTINGS_SET`）を読み書きし、デモ 1 本のセッションを Hub に始めさせる（`HUB_START`）。adb 不要
- **直接起動**: Wi-Fi adb で固定表のデモアプリを起動する（「Hub を開く」は Quest ライブラリで見つけにくい Demo Hub を前面に出すため）
- **画面ミラー**: [scrcpy](https://github.com/Genymobile/scrcpy) server v4.1 で Quest の画面を表示する（表示のみ・音なし・入力なし）

このアプリは触覚（UDP 7700）を送らない。

## 対応 Android

**Android 8.0（API 26）以上**。低遅延デコードフラグ（`KEY_LOW_LATENCY`）は Android 11 以上でのみ有効。廉価タブレットでも動くよう、ミラーの既定値は控えめにしている。

## ビルド

Android Studio 同梱の JDK を使う（PowerShell）。

```powershell
cd android/demo-remote
$env:JAVA_HOME='C:\Program Files\Android\Android Studio\jbr'
.\gradlew.bat assembleDebug
```

- APK: `app/build/outputs/apk/debug/app-debug.apk`
- インストール: `tools\install-demo-remote.cmd` をダブルクリック（`-Build` を付けるとビルドから）。USB またはワイヤレスデバッグで見えている全スマホ・タブレットに入れて起動する（Quest は除外）
- Wi-Fi でインストール（Android 11 以上）: スマホの「開発者向けオプション > ワイヤレスデバッグ」を ON。初回だけ「ペア設定コードによるデバイスのペア設定」に出る IP:ポートとコードで `powershell -File tools\install-demo-remote.ps1 -Pair 192.168.0.50:37123 -Code 123456`。以後はワイヤレスデバッグが ON で PC と同じ LAN にいれば、ケーブル無しで見つかる（mDNS）
- `local.properties`（`sdk.dir=...`）は各 PC で用意する（commit しない）
- scrcpy-server はビルド時に GitHub Releases から取得し、SHA-256 を検証して APK に同梱する（repo には置かない）。`tools/quest-mirror/scrcpy/scrcpy-server` に同じハッシュのファイルがあればそれを使う（オフラインビルド用）
- ユニットテスト: `.\gradlew.bat :app:testDebugUnitTest`
- デモボタンのサムネイル（`app/src/main/assets/thumbs/<demo_id>.webp`）は devtools-site のショーケースから縮小して同梱している。ショーケースの画像を更新したら差し替える

## 初回設定

1. 起動時に認証モードを選ぶ。現在のデモ受信側はすべて **署名なしモード** なので、外部から隔離したデモ専用 LAN では「隔離 LAN で署名なしを使う」を選ぶ。受信側に shared secret を設定している場合は同じ値を入れる（保存後は「設定済み」とだけ表示される）
2. Quest は Demo Switch の自動探索（5 秒ごと）か 5555 走査で一覧に出る。一覧は **今見えている Quest だけ** で、保存しない（直近 2 回の探索のどちらかでデモが応答した／直近の 5555 走査で開いていた／adb が接続中・接続済み・許可待ち、のどれにも当たらなくなると消える。選択中でも消え、選択も外れる）。スリープ中や別のネットワークの Quest は出ない。設定画面から IPv4 を手動追加・ラベル変更もできる（手動で追加したものも、見えなくなれば消える）
3. **宛先は一覧から自分で選ぶ**（複数の Quest が応答しても自動では選ばない）。前回選んだ Quest だけはシリアル（不明なら IP）で覚えていて、見えたら自動で選ぶ
4. ラベルは「HMD #n」の番号で、その起動中だけ使う。シリアルが分かっている Quest は、一度消えて戻っても同じ番号になる。adb で確認する前は「未確認 .37」で、デモが状態問い合わせに機種名（`device_model`）を返すと「Quest 3 · .37」になる
   - Unity / Unreal のエディタで動いているデモ（状態問い合わせの `editor` が true）は、既定で一覧に出さない。出すときは「設定 → Quest 一覧 → PC のエディタも表示」を ON にする（選択中のものは常に出る）。機種名・エディタかどうかを返さない古いデモは、今までどおり一覧に出る
5. 選んだ Quest に adb 接続すると、初回はヘッドセット内に USB デバッグの許可ダイアログが出る。「このコンピューターから常に許可」にチェックして許可する（アプリは最大 30 秒待つ）

Android 端末と Quest は **同じ LAN** に接続する。

## Hub のプリセット（デモ開始タブ）

プリセットは **HMD 内の Demo Hub に保存される**（枠は 1〜3）。スマホには保存しないので、**HMD ごとに中身が違う**。「デモ開始」タブの「プリセット（Hub に保存）」には、選んでいる HMD の Hub のプリセットが出る。

- 読み込み: 選んだ HMD の前面が Hub のとき（状態問い合わせで `demo_hub`）、プリセット 1〜3 を Demo Switch で読む。HMD を選んだとき、Hub が前面になったとき、保存したあと、「再読込」を押したときに読み直す
- 表示: 枠ごとに番号、名前、Hub のトップに表示するか、デモの並び（オプション・「もう一度なし」を含む）。中身の無い枠は「空き」
- **adb が繋がっていなくても、Hub が前面なら編集と開始ができる**（UDP だけを使う）
- Hub が前面にないときは「Hub が起動していません（「Hub を開く」で開けます）」と出て、編集と開始が押せない。最後に読んだ内容は灰色で残る（「下は最後に読んだ内容です」）。Hub は起動しているが、HMD 内でメニュー・一時停止・境界設定が開いているときは「Hub が前面にありません」と出る
- **開始**: 「開始」→ 確認画面（HMD 名とデモの並び）→「始める」。Hub がセッションを始め、1 本目のデモが前面に出ると結果ログが READY になり、前面アプリの表示が変わる。デモが 1 本もインストールされていない枠は Hub が断る
- **編集**: 「編集」で名前（空でも可・40 文字まで）、Hub のトップに表示するか、デモの並び（↑↓・削除・追加）、各デモのオプション（値を 1 つ選ぶ。最初はデモの既定値が選ばれている。既定値を選ぶと保存時にキーごと省く）、「もう一度（完了後にもう一度遊べる）」を変える（OFF の枠は一覧に「・もう一度なし」と出る）。デモを全部外して保存すると空きになる
  - 「デモを追加」の候補は、Hub の設定を読めていれば **その HMD の Hub に入っているデモ**（Hub の並び順）。アプリの表に無いデモも Hub の表示名で追加でき、オプションは既定のまま。読めていないときはアプリの表のデモ
  - 1 回の送信は 1024 バイトまで。編集画面に **残りのバイト数** が常に出る（最大の sequence と認証の署名を含めた大きさで数える）。マイナスになると保存できない。デモ数か名前を減らす
  - 「Hub に保存」を押すと、Hub が受け付けて（ACK）保存し終わる（READY）まで待ち、「保存しました」か失敗の理由を出す。結果ログにも出る
  - 主な失敗: 「〇〇 が HMD にインストールされていません」（その HMD に無いデモ）、「〇〇 にない設定です」（Hub とアプリの版違い）、「Hub が受け付けませんでした」（起動中など。閉じてからもう一度）
  - Hub の管理画面が開いている間（状態問い合わせの `screen` が `manage`）は、Hub がプリセットと設定の書き込みを断る。編集画面に「Hub の管理画面が開いています」と「管理画面を閉じる」が出る（押すと Hub がトップに戻る。管理画面で保存済みの内容はそのまま）
  - Hub の読み込みで「大きすぎて読めないデモがあります」と出た枠は、このアプリでは編集できない。Hub の管理画面で編集する
- Hub 全体の設定（触覚ボタン・リセットボタンの表示、手の見た目、スタッフ待機モード、トップに出すデモ）はプリセットに含まれない。下の「Hub の設定」で変える

**運用（展示）**: スタッフが事前に各 HMD の Hub にプリセットを用意しておけば、当日はアプリが無くても、Hub のトップ画面でプリセットを選んで開始できる（「Hub のトップ画面に表示する」を ON にした枠だけが出る）。アプリからは、HMD を選んで「開始」を押しても始められる。

## Hub の設定（デモ開始タブ → 「Hub の設定」）

Hub の管理画面で変えられる Hub 全体の設定を、選んでいる HMD の Hub から読み、書き換える（`HUB_SETTINGS_GET` / `HUB_SETTINGS_SET`、adb 不要）。プリセットと同じく HMD ごとに別。

- 読み込み: Hub が前面になったとき（プリセットと一緒）、保存したあと、「再読込」を押したとき
- 変えられるもの: 触覚ボタンを表示（起動時の既定）、視線リセットボタンを表示（起動時の既定）、手の見た目（ゴースト / 肌）、スタッフ待機モード、トップに出すデモ（Hub に入っているデモのタイル。塗りつぶし = 表示、枠だけ = 非表示。押すと切り替わる）
- 読むだけ: この HMD の宛先（プレイヤー / グループ。adb で書き込む宛先ファイルを Hub が起動時に読んだ値。「指定なし」は未指定・ファイル無し・不正）
- 「Hub に保存」で 4 つの値とタイルをまとめて送り、Hub が保存し終わる（READY）と読み直す。Hub が前面でないときや管理画面が開いているときは、プリセットと同じ案内が出て保存できない

## デモ 1 本で始める（デモ開始タブ）

デモとオプションを選んで、Hub 経由のセッション（チュートリアル・完了画面付き）として始める。候補は、Hub の設定を読めていれば Hub に入っているデモ、読めていなければアプリの表のデモ。

- Hub が前面: Hub に `HUB_START` を送る（adb 不要）
- ほかのデモが前面: adb が繋がっていれば adb（Hub の起動 extra）で始める。adb が無ければ、まず Hub に切り替え（`SWITCH demo_hub`）、Hub が前面になったのを状態問い合わせで確かめてから（最大 10 秒）`HUB_START` を送る
- デモが応答しない（ホーム画面など）: adb が繋がっていれば adb で始める。無ければボタンが押せない（理由がボタンの上に出る）
- アプリの表に無いデモ（Hub にだけ入っているデモ）は、adb では始められないので Demo Switch だけを使う
- **長押し（1 秒）**: そのデモを選び、表示中のオプション（別のデモから長押ししたときは既定値）で「このデモで始める」と同じ開始をする。押している間はタイルの下端にバーが伸び、指を離すかずらすと取り消し。始められないときは理由がボタンの上の 1 行に数秒出る
- オプションは値を 1 つ選ぶ（最初はデモの既定値が選ばれている）

## 操作タブ

送る前に前面のデモを確認し、そのデモへ `CONTROL` を送る。状態（`STATE`）で押せないボタンは灰色になり、各グループの下の 1 行に理由が出る（ボタンの位置・大きさは変わらない）。

- 進行 / 視線・触覚 / HMD 内のボタン表示 / Volley / Energy Duel: 従来どおり
- **手の見た目**: ゴースト / 肌。今の見た目が塗りつぶしで出る。共通の手を使っていないデモ（状態に `hand_style` が無い）では押せない。Hub で押すと Hub 全体の設定が変わって保存される。セッション中に押すと、次のデモにも引き継がれる
- **セッション**: 「次へ」（Hub から始めたセッション中＝`step_index` が 0 以上のとき。ポーズ / 完了パネルの「次へ」「デモを終了」と同じ）、「もう一度」（デモの完了画面が出ているとき）
- **Hub**: 「トップへ」（Hub が前面で、トップ画面以外を出しているとき。管理画面も閉じる）、「最初から（同じプラン）」（Hub の終了画面が出ているとき）

## ショーケースからプリセットを取り込む

Web のデモ紹介ページ（ショーケース）で組んだプレイリストを、選んでいる HMD の **Hub のプリセット枠に書き込む**（形式は `hapbeat-contracts` の `specs/demo-session.md`「リモコンへのプリセット受け渡し（QR / リンク）」）。書き込むだけで、セッションは始まらない。

- **QR を読む**: 「デモ開始」タブの「QR から Hub に取り込む」を押し、ショーケースに出ている QR を枠に入れる。初回はカメラの許可を求められる（拒否すると「カメラが許可されていないため QR を読めません」と出る。設定アプリから許可し直せる）
- **リンクで開く**: スマホでショーケースのページを開いた場合は「アプリで開く」を押す（`hapbeat-remote://preset?d=...`）。アプリが開いて確認画面が出る
- **確認画面**: プリセットごとに名前とデモの並び（オプション・「もう一度なし」を含む）と、**書き込む枠（1〜3）** が出る（既定は 1 件目が 1、2 件目が 2…）。中身のある枠を選ぶと「上書き: プリセット n「名前」」と赤で出る（まだ読み込んでいない枠は「中身は未確認です」）。同じ枠を 2 回は選べない。「書き込む」で順に書き込み、全部終わると閉じる。書き込んだ枠は「Hub のトップ画面に表示する」が ON になる
- **Hub が前面にないとき**: 「Hub を開いてから取り込んでください」と出て「書き込む」が押せない。確認画面は閉じないので、「Hub を開く」で Hub を出せば、そのまま書き込める
- **書き込みに失敗したとき**: 確認画面に理由が出て、閉じない（それまでの枠は書き込み済み）。直してから「書き込む」を押し直すか、「やめる」
- **エラー時**: 確認画面に理由だけが出て、何も取り込まない（一部だけ取り込むことはない）
  - 「QR・リンクの形式が違います」「プリセットの QR ではありません」: ショーケースの QR / リンク以外を読んだ。ページを開き直して読み直す
  - 「データが大きすぎます」: 700 bytes を超えている。ショーケース側でデモ数・名前を減らす
  - 「このデモはリモコンに登録されていません: xxx」: アプリの版が古い。アプリを更新する
  - 「プリセットの内容が正しくありません」「〜にない設定です」: ショーケースとアプリの版が合っていない

## Quest 再起動後の Wi-Fi adb 復旧

Quest を再起動すると、スマホからの Wi-Fi 接続（adb、TCP 5555）が切れる。アプリに「Quest の Wi-Fi adb が切れています」と出たら、次のどちらかで元に戻す。Demo Switch の切替・操作は adb なしでも使える。

**スマホと USB でつなぐ（PC 不要）**

スマホが USB ホストになって、PC の `adb tcpip 5555` と同じことをする。

1. スマホと Quest を USB-C ケーブル（データ対応）でつなぐ。アプリが開き「Quest と USB でつなぐ」が出る（アプリ表示中にスマホが周辺機器側になった時も、直し方を添えて出る）
2. 自動で始まる。初めてのスマホでは HMD を被り、「USB デバッグを許可」で「常に許可」にチェックして許可する（Wi-Fi adb と同じ鍵なので、一度許可すれば両方に効く）
3. 「完了。ケーブルを外してください（Quest の IP / prefix と SSID）」と出たらケーブルを外す（3 秒後にダイアログが閉じる）。Quest の IP を一覧に追加・選択し、Wi-Fi adb で自動接続する（1.5 秒おきに最大 6 回）

- 挿しても何も出ない時は、スマホが周辺機器側（Quest 側がホスト）になっている可能性が高い。メイン画面の「USB でつなぐ」（または「設定 → USB でつなぐ」）でダイアログを開き、「USB の状態」を見る。Quest がホスト認識済みならダイアログを開くだけで始まる
- うまくいかない時は「もう一度試す」。ダイアログの「USB の状態」で原因を切り分ける
  - 「スマホが周辺機器側（Quest 側がホスト）」: ケーブルを挿し直すか、スマホの通知の「USB の制御」で「このデバイス」を選ぶ
  - 「Quest は見えるが USB デバッグ無効」: Quest の開発者モード（USB デバッグ）を確認する
  - 「未接続」: データ通信できる USB-C ケーブルか、Quest の電源を確認する
  - 状態欄の下の小さい 1 行は、スマホから見えている USB 機器（VID:PID とインターフェース）。全文はログに残る
- 機種（`ro.product.model`）が Quest でない端末には `tcpip` を打たず「Quest ではありません」と出す
- Quest がすでに 5555 で待ち受けている時は `tcpip` を省く（adbd を再起動しない）
- Quest の Wi-Fi がスマホと別のネットワーク（サブネット）だと Wi-Fi 接続は試さず、「Quest は別のネットワークにいます」と両方の IP・SSID を出す。スマホが Wi-Fi に繋がっていない時は「スマホが Wi-Fi に繋がっていません」と Quest の SSID を出す
- スマホが USB ホストになれない端末では使えない

**PC から**

Quest を USB で PC に繋いで `tools/enable-quest-wifi-adb.cmd` をダブルクリックし、アプリで「adb 接続」を押す。

## トラブル対応

| 表示 | 意味 | 対応 |
|---|---|---|
| Quest の Wi-Fi adb が切れています | Quest には届くが 5555 が閉じている（再起動後など） | スマホと Quest を USB でつなぐ（上記。何も出なければ「USB でつなぐ」ボタン） |
| 接続中（Quest の Wi-Fi が省電力中の可能性。n 秒） | 5555 が応答しない。画面の消えた Quest は Wi-Fi が省電力になり、ARP / TCP にすぐ答えないことがある | そのまま待つ。接続前と各試行の間に Demo Switch のポート（UDP 7710）へ `DISCOVER` を数回送って起こし、約 30 秒まで間隔を広げながら試す。手動・USB 後の接続では 2 回届かないと「Quest が寝ているかもしれません」が出る（電源ボタンを短く押すか被る。つながると自動で閉じる） |
| Quest（IP）に届きません（スリープ／別の Wi-Fi／端末間通信の遮断） | 約 30 秒試しても 5555 に何も応答しない | HMD を被って画面を点ける／同じ Wi-Fi か確認（診断行）／ルーターの端末間通信の遮断（AP アイソレーション）を確認 |
| 接続待ち: Quest（IP）に届きません。n 秒後にもう一度つなぎます | 繋がっていた adb が切れ、Demo Switch ではまだ見えている | 間隔を広げながら（5・10・20・30・60 秒）自動で再接続を続ける。接続中は 20 秒ごとに短いコマンドを送って Quest の Wi-Fi を起こしておく |
| USB での有効化は成功しました。スマホから Quest に届きません | Quest 側は有効。経路の問題 | 同じ Wi-Fi か、ルーターの端末間通信の遮断を確認 |
| 接続待ち: …（灰色） | アプリ起動時・Quest 選択時の自動接続が失敗しただけ | 30 秒ごとの走査で Quest の 5555 が開いたら自動で接続し直す。すぐ繋ぐなら「adb 接続」 |
| 応答なし（デモが起動していない／スリープ／届いていない） | 「操作」の前面確認に応答がない | Demo Switch 対応デモを起動する・HMD を被って画面を点ける |
| Quest のデモが前面にありません（HMD 内でメニューや一時停止を閉じてください） | デモは起動しているが、メニュー・一時停止・境界設定などで前面にない（状態表示が「前面: X（非前面: …）」）。この間 Quest は切替・操作を断る | HMD を被ってメニュー・一時停止・境界設定を閉じる |
| Hub が起動していません（「Hub を開く」で開けます） | 選んだ HMD の前面が Hub ではない。プリセットの編集・開始・取り込みはできない | 「Hub を開く」（adb）か HMD 内で Hub を開く |
| Hub が起動していません（プリセットの読み込みに応答なし） | 前面は Hub だが、プリセットの読み込みに答えない | Hub の版が古い（プリセットの読み書きに未対応）。Hub を更新する |
| Hub が応答しません（Hub が起動していないか、Hub の版が古い） | Hub の設定の読み込みに答えない | Hub を更新する（設定の読み書きに未対応の版） |
| Hub の管理画面が開いています（閉じてから操作してください） | Hub の管理画面が開いていて、プリセット・設定の書き込みを Hub が断る | 「管理画面を閉じる」を押すか、HMD 内で管理画面を閉じる |
| 10 秒以内に Hub が前面になりませんでした | 「デモ 1 本で始める」で Hub に切り替えたが、Hub が前面にならない | HMD を被って確認する。Hub が入っていない・起動に失敗した可能性 |

選んだ Quest が adb 未接続の間（何も選んでいない間を含む）は、30 秒ごとに 5555 を走査し直す。Wi-Fi に繋がり直した時も走査する。何も選んでいない間は、前回選んだ Quest を探す（シリアルの分からない 5555 のホストに adb で接続してシリアルを比べ、一致したら選ぶ。別の IP に移っていても見つかる）。これはホストごとに 1 回だけ試す（他のブースの Quest に許可ダイアログを繰り返し出さないため）。「再探索」で試し直す。

接続済みの時のボタン「繋ぎ直す」は adb を接続し直すだけで、エラーではない。

**診断行の読み方**（Quest の状態欄の下の小さい 2 行）

- 1 行目: スマホの Wi-Fi の IP / prefix と GW。「Wi-Fi 未接続」なら broadcast も走査もしない（モバイル回線には送らない）。USB でつないだ後は、続けて USB で読んだ Quest の IP / prefix と SSID（「USB: Quest …」）
- 2 行目: 最後の探索（送信数・応答数、うち broadcast への応答）と 5555 走査（時刻・見つかった台数）

「デモ応答 ○」は Demo Switch 対応デモが **起動している** ことを表す（前面とは限らない）。メニュー・一時停止・境界設定の間も応答するが、切替・操作は断られる。前面かどうかは「前面: X」の後ろに「（非前面: …）」が出るか、「操作」タブの状態欄の「非前面」で分かる。

「デモ応答」も「adb」も × の時は、次の順に見る。

1. 1 行目: スマホが Wi-Fi に繋がっているか。GW が Quest 側のネットワークと同じか
2. 2 行目の探索: 送信が 0 や失敗が出ていれば、スマホ側の Wi-Fi・ソケットの問題
3. 応答 0 で 5555 走査も 0 台なら、Quest に何も届いていない（スリープ、別の Wi-Fi、端末間通信の遮断）。USB でつなぐと Quest の IP・SSID がログに出るので比べる
4. 走査で見つかるのに応答 0 なら、Demo Switch 対応デモが起動していない（ホーム画面など）

**ログ**: 結果ログと接続の各段階（USB の状態、getprop、Quest の IP / SSID、tcpip の応答、Wi-Fi adb の試行結果、接続時の Quest の状態）をスマホ内に保存する（最新 500 行）。「設定 → ログ → ログをコピー」で貼り付けて報告に使える。

## 画面ミラー

- 既定: 最大サイズ 1024、8 Mbps、30 fps、左目のみ（横長パネルを半分に crop）
- 設定画面で 最大サイズ 720 / 1024 / 1280 / 1600、ビットレート 2 / 4 / 8 Mbps、30 / 60 fps、「両目を表示」を変更できる。カクつく端末では最大サイズかビットレートを下げる
- デコードが詰まった時はキーフレームまで映像を捨て、2 秒以内に来なければ server を再起動する
- アプリを背面に回すと停止し、前面に戻ると再開する
- PC の `tools/quest-mirror.cmd` と同時に使える（adbd は複数の TCP クライアントを受ける）
